# Drill #8 — 호넷 애니메이션 뷰어 구현 계획

> 후속 단순화: 고정 메타데이터 검증, PNG 사전 검사, 단조 시계 dt 예외 처리, 원본 조사 모드와 미사용 필드를 제거했다. 프레임 목록·시간·배율은 한 번 계산한다. 아래 관련 검증 설계는 최초 계획 기록이며 현재 실행 요구사항이 아니다.

> 후속 변경: 사용자 요청으로 테스트 코드와 `--self-test` 옵션을 제거했다. 아래 자가검증 관련 내용은 최초 구현 당시의 계획·검증 기록이다.

> 갱신일: 2026-09-29 · 게임/캐릭터: Hollow Knight / Hornet · 렌더러: Pico2d
> 현재 상태: 구현 완료. 단일 소스, 17개 액션, 190개 고유 좌표·207개 참조, 자가검증 14개와 실제 2사이클 재생을 검증했다. 후속 요청으로 검수 모드는 명령줄 옵션 대신 I 키로 전환한다. 실행법은 [README.md](README.md), 검증 및 실제 커밋 기록은 [acceptance.md](evidence/acceptance.md)에 있다. 아래 본문은 착수 시 설계와 단계 계획을 보존한다.

## 1. 확정 제약과 이번 감사 결과

1. **과제 구현 소스는 `animation_viewer.py` 한 파일이다.** 좌표 상수, 액션 목록, 재생 제어, 렌더링, 검수 모드, 자가검증 함수를 모두 그 안에 둔다.
2. **원본 스프라이트 PNG를 그대로 한 번 로딩하고 `sheet.clip_draw(...)`로 지정 영역을 그린다.**
3. **원본 시트를 액션별·프레임별 PNG로 미리 자르지 않는다.** 새 아틀라스, 분할 이미지, 트림 이미지, 리사이즈된 스프라이트도 생성하지 않는다.
4. **17개 액션**을 구현 대상으로 유지한다. `Counter Attack`과 `Flourish`를 포함하고, 호넷 없이 이펙트만 있는 별도 영역은 재생 목록에서 제외한다.
5. 호넷과 같은 프레임에 합쳐진 궤적·섬광·참격은 그대로 표시한다. 원본 픽셀을 지우거나 중간 프레임을 빼지 않는다.
6. 최소 4종·커밋 최소 20개는 하한이다. 액션 5회 반복과 1초 정지는 정해진 값으로 지킨다.
7. 모든 추가 파일은 `Labs/LEC08_Animation/` 안에 둔다. 기존 수업 예제·다른 폴더·사용자 커밋은 보존한다.

| 기존 계획의 충돌 | 수정된 설계 |
| --- | --- |
| 여러 Python 모듈로 기능 분리 | 한 Python 파일 안에서 상수·함수·작은 데이터 구조로 구분 |
| 전처리 도구로 PNG 추출·패킹 | 전처리 도구 제거. 원본 좌표만 조사하여 코드 상수로 등록 |

이전 계획의 다중 모듈·아틀라스 구현은 시작하지 않았으며, 현재 별도 구현 소스나 자른 스프라이트 PNG는 없다. 원본 PNG를 가공하지 않는다. 사용자 확인에 따라 원본 해시 검사는 구현 요구사항에서 제외한다.

## 2. 액션과 프레임의 정의

- **액션(Action)**: 여러 프레임을 순서와 시간에 맞춰 재생하는 하나의 애니메이션 동작.
- **프레임(Frame)**: 액션을 구성하는 한 장면. 여기서는 **원본 시트 안의 사각형 좌표**로 표현하며 별도 이미지 파일이 아니다.
- **구간(Phase)**: 준비·실행·회복 등의 액션 내부 부분. 행·라벨·프레임 하나를 무조건 액션 하나로 세지 않는다.
- 예: 점프는 준비 4장 → 공중 9장 → 착지 3장으로 한 액션을 구성한다. 전체 16개 프레임을 끝까지 한 번 재생해야 액션 1회다.
- 그 전체를 5회 완료한 뒤 마지막 프레임에서 1초 정지하고 다음 액션으로 넘어간다.
- 화면 갱신 횟수와 애니메이션 프레임 전환 횟수는 구분한다. 같은 프레임을 계속 그리는 동안 반복 완료 수가 늘지 않는다.
- 같은 원본 사각형을 다른 액션이나 원본 주석의 역순 회복에서 참조할 수 있다. 이미지 복제나 고유 프레임 수 증가로 계산하지 않는다.

### 4.1. 파일 내부 데이터와 함수

- 설정 상수: 캔버스 크기, 원본 상대 경로, 5회 반복, 1초 정지.
- `FRAME_RECTS`: 고유 프레임 ID → 원본 좌측 상단 기준 `left, top, width, height`와 해당 사각형 내부의 `pivot_x, pivot_y`.
- `ACTIONS`: 액션 ID → 표시 이름, 구간, 정렬된 프레임 ID 참조 목록, 기본 FPS, 필요 시 프레임별 지속 시간.
- `ACTION_ORDER`: 전체 재생 순서. 액션 수는 목록 길이, 프레임 수는 현재 액션의 프레임 목록 길이에서 구한다.
- 함수: 데이터 검증, 경과 시간 갱신, 원본 좌표 변환, `draw_frame`, 검수/자가검증, `main`.
- 재생 상태: 현재 액션·프레임·완료 반복 수·경과 시간, `PLAYING` 또는 `PAUSING`.

별도 Python/PowerShell 도구, 테스트 모듈, 실행용 JSON 파일을 추가하지 않는다. 단일 파일 안에서 화면과 무관한 시간·좌표 계산을 순수 함수로 두어 검사한다. `if __name__ == "__main__":`에서 실행 모드를 선택한다.

### 4.2. 원본 직접 로딩과 clip_draw

1. `Path(__file__).resolve().parent`를 기준으로 원본 경로를 찾는다.
2. `open_canvas` 뒤 `load_image`로 원본 전체 PNG를 한 번 읽고 동일 이미지 객체를 재사용한다.
3. 프레임마다 원본의 사각형과 표시 기준점·배율을 계산해 그 객체의 `clip_draw`를 호출한다.
4. 프레임별 이미지 객체를 따로 만들거나 PNG를 저장하지 않는다. `clip_image`로 별도 텍스처를 만드는 경로도 사용하지 않는다.

설치된 Pico2d의 `clip_draw(left, bottom, width, height, x, y, w, h)` 구현은 원본 텍스처에 대한 소스 사각형을 사용한다. 원본 좌표를 좌측 상단 기준으로 기록할 경우 아래와 같이 변환한다.

```python
left, top, width, height = frame.rect
bottom = sheet.h - top - height
draw_x = anchor_x + (width / 2 - frame.pivot_x) * scale
draw_y = anchor_y + (frame.pivot_y - height / 2) * scale
sheet.clip_draw(
    left, bottom, width, height,
    draw_x, draw_y, width * scale, height * scale
)
```

이는 설계 예시이며 실제 소스는 아직 작성하지 않았다. 프레임 크기가 다르면 각 사각형의 폭·높이와 피벗을 그대로 사용한다. 같은 칸 크기를 가정한 `frame * 고정폭` 방식에 의존하지 않는다.

원본 높이가 13086px이므로 구현 초기에 **실제 환경에서 원본 전체 로딩과 위·중간·아래 영역의 clip_draw**를 먼저 확인한다. 이 확인은 아직 수행하지 않았다. 로딩 한계가 실제로 발생하면 오류를 기록하고 원본 직접 렌더링 범위에서 해결하며, PNG 분할을 대안으로 실행하지 않는다.

### 4.3. 좌표 검수·중앙 표시·확대

- 같은 파일의 `--inspect <액션ID> --frame <번호>` 모드에서 지정 프레임을 원본으로부터 바로 표시한다. 좌표와 번호는 콘솔에서 확인하고 PNG로 내보내지 않는다.
- 기준점을 액션 공통 좌표계에 두고 프레임 사각형 내부의 피벗 차이를 반영한다. 픽셀을 잘라 새 이미지로 만들거나 패딩 이미지로 정규화하지 않는다.
- 기본 캔버스 후보는 960×720. 대표 직립 본체 높이를 창 높이의 50% 이상으로 맞추고 각 액션 전체의 가시 범위를 검수한다.
- 종횡비를 유지하며 같은 액션 안에서는 배율을 고정한다. 회전·웅크림으로 몸체 높이가 달라졌다는 이유로 프레임마다 재확대하지 않는다.
- Counter Attack·Flourish의 합쳐진 효과를 포함해 프레임 전체가 잘리지 않는지 확인한다. 필요하면 창 비율·여백·액션별 고정 배율을 조정한다.
- 위치가 튀는 좌표 오류와 의도된 점프·회전은 구분한다. 캐릭터를 화면 밖으로 이동시키지 않는다.

### 4.4. 시간·반복·순환

- 단조 증가 시계의 경과 시간을 사용한다. 프레임 지속 시간이 끝나면 다음 프레임으로 간다.
- 액션의 마지막 프레임 지속 시간이 끝날 때만 반복 완료 수를 증가시킨다. 구간 전환은 반복 완료가 아니다.
- 1~4회 완료 후 같은 액션의 첫 프레임으로 돌아간다. 5회 완료 후 마지막 프레임을 유지하는 `PAUSING` 상태가 된다.
- 정지 1.0초 후 다음 액션의 첫 프레임으로 시작한다. 마지막 액션 이후 첫 액션으로 돌아간다.
- 큰 dt가 여러 경계를 지나도 남은 시간을 다음 상태로 넘긴다. 렌더 빈도에 따라 애니메이션 속도가 달라지지 않아야 한다.
- `delay(1)` 같은 블로킹 대기를 하지 않는다. ESC·창 닫기는 재생과 정지 중 모두 처리하고 예외에도 캔버스를 정리한다.
- 액션의 체류 시간은 `5 × sum(frame_durations) + 1초`이며 균일 FPS일 때 `5 × N / FPS + 1초`다.
- `--trace`는 액션 시작·반복 완료·정지·전환만 시간과 함께 기록한다. 매 화면 갱신을 출력하지 않는다.

### 커밋 적절성 원칙

1. 기능 또는 검수된 액션 묶음이 완성될 때 커밋한다. 한 프레임마다 커밋하거나 모두 구현한 뒤 인위적으로 쪼개지 않는다.
2. `git add .` 대신 해당 단계 파일만 선별한다. staged 파일 목록·diff·공백 검사를 확인하고 기존 수업 파일·사용자 작업을 섞지 않는다.
3. 제목과 실제 변경을 맞추고 복잡한 단계는 이유·확인 방법·남은 제한을 본문에 적는다. 미실행 검증을 통과로 쓰지 않는다.
4. 감사 시점 HEAD는 `ba08e255a34b4d78f2bf9bc7096086132475feef`다. 기존 수업 커밋은 새 과제의 최소 20개에 포함하지 않는다. 착수 직전에 실제 HEAD를 다시 확인해 시작점을 기록한다.
5. 28은 계획값, 20은 최소 조건이다. 실제로 함께 완성한 기능은 묶고 불필요한 변경은 생략하되 의미 있는 커밋 수를 계속 점검한다.
6. 빈 커밋·오탈자·공백·임시 토글·프레임 복제·동일 변경의 추가/되돌리기·날짜 조작으로 수를 채우지 않는다.
7. 기존 사용자 이력을 재작성하지 않으며 과제 이력을 최소 수에 못 미치게 squash하지 않는다.
8. 실제 해시와 검증 결과는 acceptance에 기록한다. 마지막 문서 커밋의 해시는 Git 로그로 확인하고 자기 해시를 넣기 위한 후속 커밋을 만들지 않는다.

```powershell
git diff --cached --check
git diff --cached --name-only
git diff --cached
git log --reverse --no-merges --format="%h %s" <착수직전해시>..HEAD -- Labs/LEC08_Animation
git rev-list --count --no-merges <착수직전해시>..HEAD -- Labs/LEC08_Animation
```

개수와 경로만으로 통과 처리하지 않고 각 diff의 의미를 확인한다. 폴더 밖 Slides의 Git LFS 권한 문제를 해결하려고 저장소 설정을 바꾸지 않는다.

## 7. 구현 착수 순서와 검증

1. Git 변경·시작점을 확인하고 계획/원본을 선별 커밋한다.
2. 단일 소스에서 원본 전체 로딩과 직접 clip_draw를 먼저 확인한다.
3. 원본 좌표를 조사하여 같은 파일의 상수에 등록하고 검수 모드로 17개 액션의 모든 프레임을 확인한다.
4. 중앙 표시·확대·경과 시간·5회 반복·1초 정지·전체 순환을 구현한다.
5. 같은 파일의 `--self-test`로 시간·좌표·데이터 무결성을 검증한다. 자가검증 모드는 창을 열지 않는다.
6. 실제 뷰어로 전체 액션을 2사이클 이상 재생하고 제출 문서·커밋 이력을 감사한다.

자가검증에는 범위 밖 좌표, 음수/0 크기, 빈 액션, 미존재 참조, 잘못된 시간, 5회 마지막 프레임 경계, 정지 1초 경계, 여러 상태를 넘는 dt, 서로 다른 액션 길이, 피벗/원점 변환을 포함한다. 실제 원본의 포함/제외 판정과 시각 품질은 화면 확인으로 보완한다. 임의의 4개 액션 샘플 통과만으로 17개 검수를 완료 처리하지 않는다.

예정 명령(실제 파일 구현 후 실행):

```powershell
python -B Labs/LEC08_Animation/animation_viewer.py --self-test
python Labs/LEC08_Animation/animation_viewer.py --inspect counter_attack --frame 0
python Labs/LEC08_Animation/animation_viewer.py --trace
```

과제 폴더에서 `python animation_viewer.py`로 실행하는 경우도 확인한다. README에는 단일 파일 실행법, 원본 clip_draw 구조, 액션·실제 프레임 수, 출처, 두 가산점, 자동/수동 검증 결과를 적는다.
