## 1. 목적

`sonic-sprite.png`에 포함된 소닉의 모든 애니메이션을 확대하여 자동 재생하는 데스크톱 뷰어를 만든다. 사용자가 별도의 조작을 하지 않아도 각 동작의 전체 프레임을 5회 반복하고, 1초 정지한 뒤 다음 동작으로 전환한다. 마지막 동작을 마치면 첫 동작으로 돌아가 무한 반복한다.

구현은 작은 단위로 진행하며, 실행 가능한 기능과 수정 내용을 누적하는 방식으로 20개 이상의 개발 커밋을 남긴다.

## 2. 요구사항의 근거와 기본 결정

### 2.1 기획 원본의 필수 요구사항

- Python과 pico2d를 사용한다.
- 실행 코드는 `sonic_animation_viewer.py` 한 파일로 작성한다.
- `sonic-sprite.png`의 모든 애니메이션을 재생한다.
- 동작마다 5회 반복 → 1초 정지 → 다음 동작 전환을 수행한다.
- 마지막 동작 뒤 첫 동작부터 다시 재생한다.
- 이미지를 화면에서 잘 보이도록 확대한다.
- 한 번에 전체 코드를 작성하지 않고 단계별로 구현한다.
- 개발 커밋을 20개 이상 남긴다.

다음 항목은 원본에 수치나 세부 동작이 없으므로 이 문서에서 정한 기본값이다. 구현 중 조정하면 이 문서에도 반영한다.

| 동작 순서 | 시트의 위에서 아래로, 같은 줄에서는 왼쪽에서 오른쪽으로 식별한 순서 |

## 3. 사용자와 사용 흐름

대상 사용자는 스프라이트 시트의 동작을 확인하려는 수강생과 실습 결과를 검수하는 사람이다.

1. Python과 pico2d가 설치된 환경에서 프로그램을 실행한다.
2. 창이 열리고 첫 동작의 애니메이션이 확대되어 표시된다.
3. 현재 동작의 전체 프레임을 순서대로 5회 재생한다.
4. 마지막 프레임을 유지하며 1초 정지한다.
5. 다음 동작을 같은 규칙으로 재생한다.
6. 마지막 동작의 정지가 끝나면 첫 동작으로 돌아간다.
7. ESC 키 또는 창 닫기로 종료한다.

## 4. 개발 범위

### 4.1 포함

- 원본 시트 분석과 모든 소닉 동작의 프레임 목록 작성.
- 프레임별 영역 추출, 순서 지정, 확대 및 기준점 정렬.
- 시간 기반 프레임 갱신, 반복 횟수 계산, 정지 및 동작 전환.
- 전체 동작의 무한 순환.
- 재생 중과 정지 중의 종료 이벤트 처리.
- 이미지 로드 실패 등 실행에 필요한 오류 안내.
- 동작 누락과 재생 규칙을 확인할 수 있는 검수 기록.

### 4.2 이번 버전에서 제외

- 게임 플레이, 캐릭터 이동, 충돌 처리, 배경 음악 및 효과음.
- 파일 선택 UI, 다른 스프라이트 시트의 자동 분석.
- 배속, 수동 동작 선택, 프레임 편집, 영상 내보내기.
- 시트의 제목, 제작자 표기, 장식 및 단독 정적 이미지의 애니메이션 재생.

화면의 상태 표시나 검수용 로그는 필요하면 추가할 수 있지만 필수 재생 기능보다 먼저 구현하지 않는다.

## 6. 스프라이트 데이터 설계

### 6.1 원본 분석 규칙

원본에는 크기와 간격이 다른 프레임, 여러 줄로 배치된 동작, 제목과 제작자 문구가 함께 있다. 시트 전체를 동일한 격자로 나누거나 한 줄을 무조건 한 동작으로 가정하지 않는다.

- 연속 자세를 확인하여 동작의 시작, 끝, 재생 순서를 결정한다.
- 한 동작이 여러 줄에 걸쳐 있으면 해당 구간을 연결한다.
- 한 줄에 여러 동작이 있으면 동작별로 분리한다.
- 프레임마다 원본 영역과 기준점을 확인한다. 효과나 잔상도 해당 프레임의 일부라면 포함한다.
- 동작 수와 프레임 수는 실제 분석 결과로 확정한다. 임의의 개수에 맞춰 일부 동작을 생략하지 않는다.
- 분석 결과는 코드의 동작 목록 및 주석에 기록한다. 식별이 불명확한 구간은 원본 위치와 포함 판단을 기록한 뒤 검수한다.

### 6.2 단일 파일 내부 데이터

| 데이터 | 필수 항목 | 용도 |
| --- | --- | --- |
| 프레임 | `left`, `top`, `width`, `height`, `pivot_x`, `pivot_y` | 추출할 원본 영역과 정렬 기준점 |
| 동작 | `name`, `frames`, `fps` | 동작 이름, 순서가 있는 프레임 목록, 재생 속도 |
| 재생 상태 | `action_index`, `frame_index`, `completed_repeats`, `state`, `elapsed` | 현재 동작·프레임·반복 횟수와 시간 관리 |

프레임 좌표는 원본 이미지의 왼쪽 위를 기준으로 기록한다. pico2d의 아래쪽 기준 좌표로 그릴 때는 다음 식을 사용한다.

```text
clip_bottom = image_height - top - height
```

모든 프레임은 양의 너비·높이를 가지며 원본 이미지 영역 안에 있어야 한다. 동작마다 최소 1개의 프레임이 필요하고 FPS는 양수여야 한다.

### 6.3 화면 배치

- 기본 확대율은 6배로 한다. 전체 동작의 프레임과 기준점 범위를 계산하여 창 여백 안에 들어오는 확대율을 적용한다.
- 프레임마다 확대율을 바꾸지 않아 캐릭터가 불필요하게 커졌다 작아지지 않도록 한다.
- 동작에 맞는 발 위치 또는 몸 중심을 기준점으로 사용해, 잘린 영역의 크기 차이 때문에 위치가 흔들리지 않도록 한다.
- 점프나 회전처럼 동작에 필요한 위치 변화는 유지한다.
- 배경색은 캐릭터와 구분되는 색을 사용한다. 시트의 투명 영역 또는 배경 처리 방식은 이미지 로드 결과로 확인한다.

## 7. 재생 상태와 시간 처리

### 7.1 상태 전환

| 현재 상태 | 조건 | 처리 | 다음 상태 |
| --- | --- | --- | --- |
| `PLAYING` | 현재 프레임의 표시 시간 종료, 다음 프레임 있음 | 다음 프레임으로 이동 | `PLAYING` |
| `PLAYING` | 마지막 프레임의 표시 시간 종료, `completed_repeats + 1 < 5` | 완료 횟수 증가 후 첫 프레임으로 이동 | `PLAYING` |
| `PLAYING` | 마지막 프레임의 표시 시간 종료, `completed_repeats + 1 == 5` | 완료 횟수 증가 후 마지막 프레임 유지, 정지 시간 시작 | `HOLDING` |
| `HOLDING` | 정지 시간 1초 종료 | 다음 동작 선택, 프레임·완료 횟수·정지 경과 시간 초기화 | `PLAYING` |
| 모든 상태 | ESC 또는 창 닫기 | 실행 루프 종료 및 캔버스 정리 | 종료 |

다음 동작 인덱스는 `(현재 동작 인덱스 + 1) % 전체 동작 수`로 계산한다. 완료 횟수는 0에서 시작하며, 5회차 마지막 프레임에 도달한 순간이 아니라 그 프레임의 표시 시간이 끝났을 때 5가 된다.

### 7.2 시간 계산

- `time.perf_counter()` 등 단조 증가 시계로 실제 경과 시간 `dt`를 계산한다.
- 프레임 표시 시간은 `1 / fps`로 정한다. 렌더링 루프 횟수를 애니메이션 속도로 사용하지 않는다.
- 프레임이나 상태가 바뀔 때 남은 경과 시간을 다음 구간에 전달한다. 처리 지연 때문에 프레임·반복·정지 시간이 누적해서 늘어나지 않도록 한다.
- 정지 중에도 매 루프 이벤트를 처리하고 화면을 갱신한다. 1초 동안 이벤트 처리를 막는 대기 호출로 정지를 구현하지 않는다.

프레임 수가 `N`, 속도가 `F` FPS인 동작의 이론적인 재생 및 정지 시간은 다음과 같다.

```text
동작 1회 시간 = N / F
다음 동작으로 전환하기까지의 시간 = 5 × N / F + 1초
전체 순환 시간 = 모든 동작의 (5 × 프레임 수 / FPS + 1초)의 합
```

프레임이 1개인 동작도 같은 규칙을 적용하여 해당 프레임의 표시 시간을 5회 계산한 뒤 1초 정지한다.

| 11 | 완료 반복 횟수 계산 | 마지막 프레임 표시 종료마다 1회 증가한다. |
| 12 | 5회 반복 종료 조건 | 6회차를 시작하지 않는다. |
| 13 | 마지막 프레임의 1초 정지 | 정지 중에도 종료 입력에 응답한다. |
| 14 | 두 번째 동작 등록 및 전환 | 정지 종료 뒤 두 번째 동작을 시작한다. |
| 15 | 동작 전환 시 상태 초기화 | 다음 동작도 정확히 5회 반복한다. |
| 16 | 마지막 동작에서 첫 동작으로 순환 | 두 동작으로 무한 순환을 확인한다. |
| 17 | 나머지 동작의 프레임 등록 | 분석 목록의 모든 동작이 재생된다. |
| 18 | 불규칙 영역과 기준점 보정 | 잘림과 불필요한 위치 흔들림이 없다. |
| 19 | 동작별 화면 맞춤 확대율 적용 | 모든 프레임과 효과가 창 안에 들어온다. |
| 20 | 큰 경과 시간과 상태 경계 처리 | 시간 잔여분과 반복·정지 경계가 정확하다. |
| 21 | 의존성·이미지 오류 안내 및 자원 정리 | 오류 원인을 알 수 있고 종료가 정상이다. |
| 22 | 전체 동작 및 2회 순환 검수, 결과 기록 | 수용 기준을 확인하고 필요한 수정까지 완료한다. |

작업 순서는 기능 의존성에 맞춰 조정할 수 있지만, 전체 코드를 한 번에 작성한 뒤 커밋만 나누는 방식은 사용하지 않는다. PRD 작성 커밋과 별개로 구현 과정에서 20개 이상의 개발 커밋을 확보한다.

## 10. 수용 기준과 검수 방법

| ID | 검수 방법 | 통과 기준 |
| --- | --- | --- |
| AC-01 | 저장소 루트와 `Labs/LEC09`에서 각각 실행 | 추가 코드 파일 없이 같은 이미지로 실행된다. |
| AC-02 | 원본 시트와 등록된 동작·프레임 목록을 대조 | 모든 소닉 애니메이션이 포함되고 제목·제작자 문구가 프레임에 섞이지 않는다. |
| AC-03 | 각 동작을 육안으로 재생 확인 | 프레임 순서가 자연스럽고 인접 프레임 잘림이나 불필요한 위치 흔들림이 없다. |
| AC-04 | 상태 갱신 함수를 확인하거나 임시 전환 로그로 추적 | 모든 동작에서 전체 프레임을 정확히 5회 재생한다. |
| AC-05 | 5회차 끝과 다음 동작 시작 시각을 확인 | 마지막 프레임 표시 종료 후 1초 정지하며, 화면 관찰 오차는 정상 실행 시 ±0.1초 이내다. |
| AC-06 | 전체 목록을 2회 이상 순환 | 매 순환에서 순서·횟수·정지가 동일하고 마지막 동작 뒤 첫 동작으로 돌아간다. |
| AC-07 | 재생 중과 정지 중 각각 ESC 및 창 닫기 실행 | 정지 종료를 기다리지 않고 이벤트 처리 루프에서 종료한다. |
| AC-08 | 가장 큰 프레임과 효과가 있는 프레임 확인 | 확대된 전체 영역이 창 안에 들어오고 캐릭터를 구분할 수 있다. |
| AC-09 | 이미지 경로를 임시로 바꾸는 등 로드 실패 재현 | 원인을 안내한다. 검수 후 원본 파일과 경로를 복원한다. |
| AC-10 | Git 로그와 변경 내용 확인 | 구현 과정의 실질적인 개발 커밋이 20개 이상이며 단계별 진전이 드러난다. |

검수 기록에는 실행 환경, 동작 수와 동작별 프레임 수, 반복·정지 확인 결과, 2회 순환 결과, 오류 및 종료 확인 결과를 남긴다. 임시 로그나 보조 검수 도구를 사용하더라도 최종 프로그램은 단일 Python 파일로 실행 가능해야 한다.

## 11. 완료 조건

- `sonic_animation_viewer.py`와 기존 `sonic-sprite.png`로 실행할 수 있다.
- 원본 분석 목록의 모든 소닉 동작이 확대되어 올바른 순서로 재생된다.
- 모든 동작에 5회 반복, 1초 정지, 다음 동작 전환 규칙이 동일하게 적용된다.
- 마지막 동작부터 첫 동작으로 이어지는 순환과 종료 처리가 정상이다.
- 수용 기준 검수를 완료하고 발견한 결함을 수정한다.
- 20개 이상의 개발 커밋으로 단계별 구현 과정을 확인할 수 있다.
